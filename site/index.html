draftsmith

A floorplan scene-graph engine

Floorplans as small semantic documents — walls, doors, windows as facts; rooms, areas, adjacency derived; DXF/SVG/PNG compiled. Built for LLM-agent drafting, synthetic dataset generation, and human design tooling.

FP1 — a floorplan in ~65 tokens

A token-efficient canonical format built for LLM context windows (~4× denser than JSON). The engine validates every document, derives rooms and connectivity with Shapely wall-body unions, and feeds precise errors back to the drafting agent until the plan is sound.

One engine, four surfaces

Agent drafting

A toolless text protocol: system prompt teaches FP1, the engine checks every reply and returns rooms/areas/connections or precise errors. Verified first-shot with frontier models.

Derived truth

Rooms, areas, door/window connectivity are computed, never stored — mitres and jambs come free from wall-body unions.

Style compiler

The same scene renders under interchangeable depictions (door, window and label styles) — the variety axis for synthetic CAD datasets.

Studio

Graphical editing with live rooms, undo, FP1 round-tripping, DXF export — and a chat panel where model output lands on the canvas, journal-recorded and undoable.

See it

The demo is fully in-browser. The real Python engine — Shapely geometry, matplotlib rendering, ezdxf export — runs in your browser via Pyodide; nothing runs on a server. Chat works out of the box in demo mode, or bring a free OpenRouter key (stored only in your browser) for live LLM drafting.

Where it's going

A drafting-agent benchmark (NL brief → DXF, scored on geometric fidelity, constraint satisfaction, and design quality), a synthetic dataset factory for floorplan recognition, and agent-behavior research on feedback modalities and intermediate representations. Details in the roadmap and research notes.
